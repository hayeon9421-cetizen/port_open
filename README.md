## git 기본으로 기억해야할 용어   
- **Commit (커밋)** : 변경한 소스를 내 로컬 Git 저장소에 기록(저장)
- **Push (푸시)** : 내 로컬 Git 저장소의 커밋을 원격(Remote) 저장소에 업로드(반영)
- **Pull (풀)** : 원격(Remote) 저장소의 변경사항을 가져와 내 로컬 Git 저장소와 소스에 반영 (Fetch + Merge 또는 Rebase)
- **Fetch (패치)** : 원격(Remote) 저장소의 변경사항을 가져와 로컬 Git 정보만 갱신. 현재 작업 중인 소스에는 직접 반영하지 않음


 
# 아래는 더 깊이 정리된 git - 추후 참조로 사용





## Git 기본 개념 및 명령어 정리

## 1. Git 주요 용어

- **Commit (커밋)**: 변경한 소스를 내 로컬 Git 저장소에 기록(저장)한다.
- **Push (푸시)**: 내 로컬 Git 저장소의 커밋을 원격(Remote) 저장소에 업로드(반영)한다.
- **Pull (풀)**: 원격 저장소의 변경사항을 가져와 내 로컬 저장소와 작업 소스에 반영한다. (Fetch + Merge 또는 Rebase)
- **Fetch (패치)**: 원격 저장소의 변경사항을 가져와 로컬 Git 정보만 갱신한다. 현재 작업 중인 소스에는 직접 반영하지 않는다.

## 2. Commit, Push, Pull, Fetch의 차이

| 명령 | 설명 | 작업 소스에 반영? |
|---|---|---|
| `commit` | 변경사항을 로컬 Git 저장소에 기록 | 로컬 변경사항을 기록 |
| `push` | 로컬 커밋을 원격 저장소로 전송 | 원격 저장소에 반영 |
| `pull` | 원격 변경사항을 가져와 로컬 브랜치에 병합 또는 Rebase | 예 |
| `fetch` | 원격 변경사항 및 원격 추적 브랜치 정보를 갱신 | 아니요 |

### Pull과 Fetch의 차이

`git pull`은 일반적으로 내부적으로 `git fetch`를 실행한 다음, 가져온 변경사항을 현재 브랜치에 Merge(병합)하거나 Rebase(재배치)합니다.

`git fetch`는 원격 저장소의 최신 커밋과 브랜치 정보를 로컬 Git에 가져옵니다. 현재 체크아웃한 브랜치나 작업 파일을 직접 변경하지 않으므로, 가져온 내용을 확인한 후 Merge 등을 직접 수행할 수 있습니다.

- **Pull**: 원격 변경사항 가져오기 + 현재 로컬 브랜치에 통합
- **Fetch**: 원격 변경사항 가져오기 + 원격 추적 정보 갱신 (통합은 직접 수행하지 않음)

> Pull은 Git 설정에 따라 Merge 대신 Rebase를 수행할 수도 있습니다.

## 3. 자주 사용하는 Git 명령어

| 명령어 | 설명 |
|---|---|
| `git clone <저장소주소>` | 원격 저장소를 처음 내 컴퓨터에 복제한다. |
| `git status` | 현재 변경사항과 Git 상태를 확인한다. |
| `git add .` | 현재 디렉터리의 변경 파일들을 커밋 대상으로 등록(스테이징)한다. |
| `git add <파일명>` | 특정 파일을 커밋 대상으로 등록한다. |
| `git commit -m "메시지"` | 스테이징된 변경사항을 로컬 저장소에 기록한다. |
| `git push` | 로컬 커밋을 원격 저장소에 업로드한다. |
| `git pull` | 원격 변경사항을 가져와 로컬 브랜치에 통합한다. |
| `git fetch` | 원격 변경사항과 브랜치 정보를 가져오되 현재 작업 소스에 직접 반영하지 않는다. |
| `git log` | 커밋 이력을 확인한다. |
| `git diff` | 변경된 내용이나 커밋 간 차이를 비교한다. |
| `git branch` | 브랜치 목록을 확인한다. |
| `git switch <브랜치명>` | 해당 브랜치로 이동한다. |
| `git switch -c <브랜치명>` | 새 브랜치를 만들고 이동한다. |
| `git merge <브랜치명>` | 지정한 브랜치의 변경사항을 현재 브랜치에 병합한다. |
| `git stash` | 커밋하지 않은 작업 변경사항을 임시 보관한다. |
| `git stash pop` | 임시 보관한 변경사항을 꺼내 적용하고 보관 목록에서 제거한다. |

## 4. 일반적인 작업 흐름

### 새 작업 또는 수정한 소스를 원격 저장소에 올리는 경우

```bash
git status
git add .
git commit -m "변경사항 설명"
git push
```

1. `git status`로 변경사항을 확인한다.
2. `git add .`로 커밋할 파일을 등록한다.
3. `git commit`으로 로컬 저장소에 기록한다.
4. `git push`로 원격 저장소에 올린다.

### 원격 저장소의 변경사항을 가져오는 경우

바로 로컬 소스에 적용하려면:

```bash
git pull
```

변경사항을 먼저 확인하고 통합하려면:

```bash
git fetch
git log --oneline HEAD..origin/main
git merge origin/main
```

> 위 예시의 `main`은 현재 사용하는 브랜치명에 맞게 바꿔야 한다. Fetch 후에는 원격 추적 브랜치(예: `origin/main`)를 기준으로 변경사항을 확인하고 통합할 수 있다.

## 5. Git 작업 흐름 한눈에 보기

```text
내 작업 파일
    │
    │ git add
    ▼
스테이징 영역 (커밋 준비)
    │
    │ git commit
    ▼
로컬 Git 저장소
    │
    │ git push
    ▼
원격 Git 저장소 (GitHub / Gitea 등)
```

원격 저장소의 변경사항을 내 컴퓨터로 가져오는 흐름:

```text
원격 Git 저장소
    │
    │ git fetch
    ▼
로컬 원격 추적 정보 갱신
    │
    │ git merge (또는 git rebase)
    ▼
내 로컬 브랜치 및 작업 파일에 반영
```

`git pull`은 일반적으로 Fetch와 통합(Merge 또는 Rebase)을 한 번에 수행한다.

## 6. 용어 간단 정리

- **Repository (저장소)**: Git이 파일 변경 이력을 관리하는 공간.
- **Local (로컬)**: 내 컴퓨터에 있는 저장소.
- **Remote (원격)**: 서버에 있는 저장소 (예: GitHub, Gitea).
- **Working Directory (작업 디렉터리)**: 직접 파일을 수정하는 공간.
- **Staging Area (스테이징 영역)**: 다음 Commit에 포함할 변경사항을 준비하는 공간.
- **Branch (브랜치)**: 기존 작업 흐름과 분리해 개발할 수 있는 작업 경로.
- **Merge (병합)**: 서로 다른 브랜치의 변경사항을 하나로 통합하는 작업.
- **Rebase (리베이스)**: 커밋의 기반을 다른 커밋 위로 옮겨 커밋 이력을 재구성하는 작업.
- **Remote-tracking branch (원격 추적 브랜치)**: Fetch로 갱신되는 원격 브랜치 상태의 로컬 참조 (예: `origin/main`).
